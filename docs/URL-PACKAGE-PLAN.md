# URL reification plan

Status: U0/U1 setup and U2a inventory verified; U2b strict join tested and
source-span inputs reviewed; semantic census still open, 2026-09-05,
on `codex/url-reification`
from `main` at `c1c7caa`. The requested end state is the WHATWG URL Standard
reified in Lean 4 with specification-level algorithms and laws, strong proof
assurance, and idiomatic native Lean APIs. A pin or compiling scaffold alone
does not meet that objective.

## Authority and ownership

`SPEC-MANIFEST.md` owns the URL source pin and section dispositions.
`docs/PROVENANCE.md` owns upstream identity, fetch commands, licenses, and
digest cross-checks. `docs/ARCHITECTURE.md` owns module boundaries. This file
owns URL phases, entry/exit gates, and the current handoff.

The setup follows Infra's W5 and HTML's H0/H1 in the existing `whatwg`
package. `Whatwg.Url` is the consumer root, imported from `Whatwg.lean` and
therefore from the common axiom audit. It adds no Lake package or dependency.
The existing pinned toolchain, warning policy, gates, and CI apply.

The URL upstream tree supplies `url.bs`, its license, and its contribution
README. It has no Streams-style reference-implementation directory. No
third-party URL implementation is silently promoted to semantic authority.

Before developing one area deeply, U2 freezes a representative contract for
percent encoding, hosts, the URL record/parser, serialization/equivalence,
origins/rendering, form encoding, and each API class. A separate breaker
process commits contracts and a red battery before builder implementation.
Red modules use `test/fixtures/trust-gate/known-red.txt`; stable URL attack IDs
join the central counterexample register. Frozen theorem statements remain
unchanged by builders.

Native Lean decisions are made against the exact installed core/Std APIs and
existing Infra owners, with measurements when representation choices affect
kernel reduction or compiled execution. A convenient carrier, finite probe,
or automation tactic is not evidence of semantic fidelity. No `sorry`, new
axiom, `native_decide`, or `bv_decide` closes an obligation.

The user's 2026-09-05 objective additionally minimizes `Classical.choice`
in proofs as far as practical. Constructive definitions and proofs are the
default for this lane. Each semantic declaration's receipt must inspect its
actual transitive axioms, including dependencies in its statement; absence
of a written `classical` command is insufficient. Prefer the canonical
Infra byte/code-point/string carriers, explicit decidable predicates and
structural induction. Before retaining a dependency on choice, identify its
exact path and try a constructive proof or an existing constructive API.
Keep any remaining dependency and the reason it remains in that declaration's
assurance record. Tooling and host-facing text adapters have separate receipts
so their dependencies cannot be mistaken for a requirement of URL semantics.
The repository's standard-base ceiling still rejects forbidden axioms; its
permission for `Classical.choice` is not this lane's proof-quality target.

## Dependency questions to close at U2

Infra already owns byte, code-point, scalar-value, and JavaScript string
carriers. Reuse them; name any checked view or adapter and its conversion law.
Lean `String` cannot silently replace a UTF-16 string containing unpaired
surrogates. Validation errors may accompany successful parses and must not be
collapsed into failure.

URL invokes Encoding, Unicode UTS #46, Web IDL, HTML, the File API, and the
Public Suffix List for public suffix and registrable domain algorithms. Its
requirements also refer to the IANA URI Schemes registry and Unicode bidi
rendering behavior. Their
exact algorithms, tables, versions, and admitted host boundaries need explicit
rows before use. URL's pure helpers and parser have first-order inputs and
outputs; URLSearchParams association and API mutation need explicit state and
observation laws. Streams' promise tape and masks are not automatically URL's
observation model. Each URL contract must name its own observation projection
and explain any relation to the common masks.

The fetched WPT `url/` directory includes parser, setters, form, IDNA, and API
fixtures. It is corpus material only: browser infrastructure, `/resources`,
IDL interfaces, and cross-directory Encoding/HTML cases are not bundled by
this slice. WPT's own `url/README.md` locates encoding-argument tests under
`/encoding` and `/html/infrastructure/urls/resolving-urls/query-encoding/`.
Pin the required runner and these inputs before claiming any host result.

### Census scanner acceptance requirements

Independent review of the pinned URL bytes found that neither existing
`Gates.Census` profile suffices unchanged. The Streams profile requires its
piping list and only recognizes `<xmp class="idl">`, whereas URL has two
`<pre class=idl>` blocks. The Infra definition profile misses IDL and unnamed
algorithm blocks, including API setters and origin extraction. URL's bare
`id=` and `for=` attributes also require the general attribute reader.

U2 must account for all 208 definition openers, 72 algorithm blocks, 21
parser-state definitions, and two IDL blocks independently counted at this
pin. These are scanner cross-checks, not specification coverage. Definition
spans must include associated tables (special schemes/default ports), brief
unordered lists (Windows drive-letter and valid-URL grammar), and table-cell
error definitions. Parser states need their own body spans and a parent
parser relationship. The current next-blank-line and next-ordered-list rules
can omit necessary text or absorb an unrelated algorithm. Add executable
scanner contracts for those shapes before admitting the URL census.
